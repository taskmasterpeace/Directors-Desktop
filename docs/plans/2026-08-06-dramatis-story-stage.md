# Dramatis Story Stage — character-voiced stories on the DD timeline

**Goal (Robert, 2026-08-06):** stories told by CHARACTERS, not just a narrator —
per-character voices, sound effects, ambience, score — generated by Dramatis
(Audio Movie Studio, `D:\git\dramatis`) and placed on the Directors Desktop
editor timeline as **separate elements**, never a mixdown. Full GUI (cast,
scenes, cues), a points/cost story, meticulous edge cases, wow-grade polish.

## Why Dramatis is the engine (not a rebuild)

Dramatis already solves the hard audio problems and has laws we inherit:
- **Speaker attribution** per line (deterministic cascade + LLM verify, golden-file tested)
- **Computed casting** — gender/age/accent inference → per-engine voices; auditions; saved actors
- **SFX retrieval, not guessing** — CLAP over ~2,400 CC0 clips, placed at
  anchor-word onset by forced alignment, per-cue confidence, approve/swap/reject
- **Hybrid engine routing** — kokoro narration (free), qwen3 dialogue (free,
  local clone), ElevenLabs/Gemini hero lines only (dollars, metered)
- **book.json carries visuals already** — every entity and scene has a `visual`
  description written for the motion-comic phase. The video half was planned for.
- Studio server (`node studio/server.mjs` → :4600, zero deps): bookshelf, cast
  editing, auditions, SFX approval, render with SSE logs, pre-flight cost.

## The one honest data source

`mix()` (dramatis `src/mix.mjs`) already computes the exact un-mixed timeline in
memory: per-line `{id, entity, start, dur, text, norm(levelled wav)}`, per-cue
`{file, at, confidence}`, per-scene beds, music shots. Today it throws that
away after building stems. **Piece 1 makes mix() also write `dd-elements.json`**
— absolute media paths + times for every element. No second timing authority,
no drift: the file is emitted by the same code that placed the audio.

## Architecture (3 pieces)

1. **Dramatis emitter** (patch in `D:\git\dramatis/src/mix.mjs`):
   `out/<book>/ch-NN/dd-elements.json` = `{ book, chapter, heading, durationSec,
   entities[{id,kind,names,visual}], scenes[{id,start,end,visual,ambience}],
   lines[{id,entity,start,dur,text,wav}], cues[{id,sfx,at,file,confidence,gainDb}],
   beds[{sceneId,file,start,end,gainDb}], music[{id,at,file,spec,license}] }`.
   Paths absolute. Written on every mix — content lives beside timing.json.

2. **DD backend** `handlers/dramatis_handler.py` + `_routes/dramatis.py`:
   - `dramatis_root` setting (default `D:\git\dramatis` when present)
   - `GET /api/dramatis/status` — root found, studio running (probe :4600), books
     (id/title/chapters/freshness: has dd-elements? mtime vs book.json?)
   - `POST /api/dramatis/studio/start|stop` — managed `node studio/server.mjs`
     child (comfy-pattern lifecycle; never two)
   - `GET /api/dramatis/book/{id}` — cast/scenes/voices + per-chapter artifacts
   - `GET /api/dramatis/export/{book}/{ch}` — dd-elements.json, validated, each
     media path existence-checked (`missing: true` flags, never silent)
   - Renders/auditions: the RENDERER talks to studio :4600 directly (both are
     localhost); backend only guarantees the process exists. Fallback if CSP
     bites: thin backend proxy.

3. **DD frontend**:
   - `lib/dramatis-loader.ts` (pure, vitest-covered): dd-elements → `Timeline`
     with tracks `V1 Scenes / A1 Dialogue / A2 SFX / A3 Ambience / A4 Music`,
     one audio clip per line/cue/bed/music at its true time (file:// URLs), and
     read-along `subtitles[]` ("Entity: text") — plus a cast/scene index for the
     view. Missing-media elements become placeholder-named clips (import-modal
     precedent) and are reported, not dropped silently.
   - `views/Dramatis.tsx` — the Story Stage. Left rail: bookshelf w/ freshness +
     studio pill. Main: cast panel (visual descriptions, per-engine voice chips,
     audition play), chapter cards (stage state, duration, line/cue counts),
     cue audit strip (confidence bars, approve link into Studio), cost card,
     and the money button: **"Place on timeline"** → `importDramatisChapter`
     (mirrors `importPaletteMv`: new project → land in the editor).
   - Home nav: CREATE → "Story Stage" entry.

## Points system (honest version)

Dramatis is local-first: kokoro narration, qwen3 character voices, ACE-Step
score, CLAP SFX — **$0, 0 pts, runs on the 4090**. Money only enters for hero
lines (ElevenLabs ~$0.11/1k chars) and Gemini auditions via Robert's own keys.
The cost card therefore shows: `Local engines — free · Hero lines: ~$X.XX
(ElevenLabs, your key) · 0 Palette pts`, with X from char-count × the same rate
the Studio pre-flight uses. If a future path routes premium TTS through
Palette, pts = cents, same as everywhere else in DD. No fake pts on local work
(the law from the "(10 pts)" incident).

## Edge cases (each gets explicit handling, not luck)

- Dramatis root missing/moved → status says so; view shows a setup card with a
  folder picker, never a crash. Root persisted in settings.
- Studio port 4600 already busy by a foreign process → probe identifies
  non-studio responses; surface "port busy" instead of proxying garbage.
- Book with no renders yet (no dd-elements.json) → chapter card shows "Render
  first" CTA wired to Studio; import button disabled with the reason inline.
- Stale export (book.json newer than dd-elements.json) → amber "stale — re-render
  to refresh" chip; import still allowed (it's what exists), staleness carried
  into the project name suffix.
- Levelled WAVs pruned from cache → export validation flags each missing file;
  loader places placeholder clips; import summary lists them (count + first few).
- Re-import of the same chapter → new project each time (Palette-MV precedent);
  no in-place merge in v1.
- Apostrophes/spaces in paths → file:// URLs via the shared pathToFileUrl;
  ffmpeg-side escaping is dramatis's problem and already solved there.
- Cues skipped by dramatis (unresolved/low-sim) → they are absent from
  dd-elements by design; the cue audit shows them as skipped with reason.
- Entities with kind narrator → cast panel groups narrator separately; lines
  still land on A1.
- Chapter durations 100+ min → per-chapter import only in v1 (whole-book merge
  is a later phase; the loader API takes one chapter).

## Deliberately deferred (named so they're choices, not gaps)

- **Voice isolation** for actor seed clips from mixed audio (Demucs lives in the
  Palette MV stack; wiring it into dramatis `actors/` intake is Phase 2).
- **Scene stills / H3 video on V1** — entity+scene `visual` fields are surfaced
  (copyable) in the view now; auto-generation onto V1 is the motion phase.
- Whole-book (multi-chapter) single-timeline merge.
- In-place re-sync of an already-imported project.
